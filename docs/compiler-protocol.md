# Compiler machine interface

PB-060 P1.0, 2026-09-05.

`ingestron version --output json` retains `result.version` and additionally
returns `result.compiler`, with contract `ingestron.compiler-protocol/v1` and a
`commandResults` map. Consumers check the distribution version separately from
these semantic result identifiers.

| Command                     | Result contract                               |
| --------------------------- | --------------------------------------------- |
| `project resolve`           | `ingestron.contract-base-resolution/v1`       |
| `project validate`          | `ingestron.project-validation/v1`             |
| `gen plan`                  | `ingestron.generation-plan/v1`                |
| `gen build`                 | `ingestron.generated-project/v1`              |
| `gen verify`                | `ingestron.generated-project-verification/v1` |
| `deploy plan`               | `ingestron.deployment-handoff/v1`             |
| `project draft-discovery`   | `ingestron.discovery-draft/v1`                |
| `project import-discovery`  | `ingestron.discovery-import/v1`               |
| `project inspect-standards` | `ingestron.standards-catalogue/v1`            |
| `project bind-standard`     | `ingestron.standards-binding/v1`              |

`src/project.ts`, `src/discovery-draft.ts`, `src/standards-bindings.ts` and `src/layered-standards.ts` own these
commands' compilation, drafting and standards semantics.
Studio invokes this CLI through its server worker; terminal and CI invoke the
same commands. Handshake identifiers do not validate complete schemas, guarantee
backward compatibility or attest to executable integrity. Preserve the existing
version/digest installation controls.

The historical `product` commands use the separately versioned Blueprint process
and are not included in this compiler protocol. They are retained for backwards
compatibility while requirements/discovery composition is consolidated. Do not
add a second standard resolver or target renderer there for the new delivery
journey.

Discovery import now runs entirely in the CLI; it no longer needs Blueprint or
a Studio-side mapper. [Discovery drafts](discovery-drafts.md) explains review,
limits and recovery. [Layered standards](layered-standards.md) explains exact
organisation/infrastructure/ELT bindings. Compiler resolve, validation, plan,
build and deployment-handoff responses include an optional
`deliveryStandards` lock when those bindings are used; legacy output is unchanged.

The Studio repository owns `pnpm test:compiler-parity`, a real-process comparison
of plans and generated bytes across its job adapter and terminal execution.
Run it against the rebuilt compatible release set before shipping compiler or
adapter changes. This branch adds source interfaces only; it does not release a
new package or change existing Apache/runtime licensing boundaries.
